## Goal
At the very end: run the game natively on the phone instead of through Wine + Box64, for better speed and battery.

## Notes

## Static recompilation (2026-10-15, colleague's NgBMX approach)
The colleague recompiles a 32-bit 1999 DirectX 6/7 game: x86 -> C -> native ARM64, with a small Rust runtime
(DirectDraw/Direct3D 3 -> Vulkan/GLES, DirectSound -> AAudio, DirectInput -> touch). Same idea for DSR is possible but
much bigger:
- **Size:** DSR is ~20 MB of x86-64 code (NgBMX is a few hundred KB), C++ with vtables, exceptions, SSE/AVX, Havok
  physics, multithreading (job system), and jump tables. The lifting must handle all of it without bugs; one wrong
  instruction = random crash hours into play.
- **Runtime:** D3D11 (not DX6): reuse DXVK natively on ARM (Vulkan) instead of writing a renderer. Plus XAudio2/FMOD,
  Bink video, Steam API, Win32 threads/files/sync. Wine already does all of this; a custom runtime re-does it.
- **Gain:** the CPU side. Box64 (x86 -> ARM translation at run time) is the bottleneck (main thread, ~30 FPS cap,
  heat). Native code could be ~2-3x faster on the CPU and cooler. GPU work stays the same.
- **Our UI work carries over:** menu.drb patches, the agent's patches (they become source-level patches), the app's
  touch layer and controls (the runtime would feed the same inputs).
- **Decision:** last (after v1.0.0), as planned. Reason: months of work before the first frame; the UI / controls
  being built now are needed in both versions, and the current build is the reference to test a recompiled build
  against. Revisit earlier only if Box64 heat / speed blocks normal play.
