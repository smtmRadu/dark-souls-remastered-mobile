Dark Souls Remastered · Android port · Galaxy Z Flip6

Kindled Touch Controls

Six touch-layout proposals for the Flip6 inner screen (2640×1080, 22:9, ~425 dpi → 1 dp = 2.66 px, screen = 992×406 dp). Every mockup is drawn to scale in dp over real screenshots. Use the tabs under each mockup to switch states. Use the toolbar to swap the left-hand item and to hide the overlays.

Summary

  • The game draws 16:9 (722×406 dp) in the centre. Two black bars of 135 dp sit left and right. Those bars are free space for controls.
  • The stock equipment HUD (bottom-left of the game image) sits exactly under the left thumb. All proposals move it. Most turn it into a tappable d-pad: its diamond shape already matches the d-pad.
  • Menus and cutscenes show no overlay. A mod DLL reports game state; the touch layer hides itself.
  • Lock-on is a tap on the enemy. The DLL projects enemies to screen space and snaps to the nearest one.
  • Recommendation: #6 Adaptive Hybrid — stick and HUD in the left bar, an attack arc that mostly lives in the right bar, context buttons and gesture shortcuts on the buttons. Add #5 Flex Deck as an automatic second posture later.

Shared rules (all proposals)

Visibility

  • The DLL publishes state flags: in_menu, in_cutscene, loading, dialog_open, prompt_available (+ prompt type), lock_target, left_hand_is_shield, quick_item + count.
  • Menu, dialog, cutscene or loading → the overlay fades out in 150 ms. Taps then act as mouse clicks; drags act as scroll.
  • Gameplay → controls fade in to 45 % opacity. They rise to 70 % while touched or while locked on.
  • The Android back gesture = Cancel/B in menus and = open menu in gameplay.
  • Context buttons (Talk, Pick up, Open, Pull lever, Rest at bonfire) appear only while prompt_available is true. Their icon follows the prompt type.

Touch rules

  • Slide-through: a finger that slides onto another button presses it. Shield → Attack slide = guard-attack without lifting.
  • Tap vs drag (free area): tap = <180 ms and <8 dp travel. Anything else is camera.
  • Button gestures (swipe on a button) need ≥ 22 dp travel inside 220 ms. The tap action is sent on release only for gesture-capable buttons, so add 0 ms delay for plain buttons.
  • Multitouch: 3 simultaneous fingers minimum (stick + camera + button).

Camera

  • Drag on any free area = look, GTA SA style: finger delta → camera angle delta, no stick-style acceleration.
  • Best path: the DLL writes camera yaw/pitch directly. Second best: send raw mouse deltas (DSR PC supports mouse look). Note: mixing mouse and pad makes DSR flip button prompts; the DLL should force pad prompts.
  • Fallback: emulate the right stick with a velocity curve. This feels laggy; keep it only as a fallback.

Lock-on (replaces R3)

  • Tap an enemy → lock. Tap the locked enemy → release. Tap another enemy → switch.
  • The DLL maps the tap from screen space to game viewport space (subtract the 360 px bar, scale 1920→1280), projects lockable characters, and picks the nearest within 40 dp (106 px). No hit → nothing happens (no camera reset).
  • While locked, a horizontal flick that starts on the target = switch target left/right (the console right-stick flick).
  • Feedback: ember ripple on tap, corner brackets + ember dot, short haptic tick. Release: brackets fade.

Shield ↔ left-hand weapon

Toggle "Left hand" in the toolbar. The Block button turns into L-Attack (dagger icon with "L" mark) when left_hand_is_shield is false. The HUD slot shows the same change.

Verdict

Recommended#6 Adaptive Hybrid, built in this order:

  1. Margin-first layout: stick home and the equipment-HUD d-pad in the left bar; the attack arc mostly in the right bar. Only ~6 % of the game image is covered (a slim strip on the right edge).
  2. Context-only buttons (Talk / Pick up) and the hide-in-menus rule. This is the largest "native mobile" win.
  3. Tap-to-lock in the DLL. This removes the hardest controller input from the touch layout.
  4. Button gestures as optional extras: swipe Shield outward = parry, long-press Item = radial with Estus pinned.
  5. Later: #5 Flex Deck as a second posture. Jetpack WindowManager reports FoldingFeature.State.HALF_OPENED; switch the layout automatically.

Why not the others as-is: #1 covers too much of the right side of the game image. #2 is excellent for view but cramped (most buttons 52 dp). #3 is elegant but the gestures add misfires in tense fights. #4 needs thumb hopping between 12 buttons. #5 shrinks the game image to a ~2.9-inch view.
